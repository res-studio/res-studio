# Help people discover RES Studio

GitHub repository search normally matches the **repository name, description and topics**. README content is searchable with `in:readme`. For discoverability, keep metadata accurate and descriptive.

## Repository About metadata

Open [the repository](https://github.com/res-studio/res-studio), select the gear icon beside **About**, then set:

**Description (copy):**

```
Open-source web asset scanner and JavaScript bundle analyzer. Inspect HTML/CSS/JS, explore bundles with Webcrack, and use MCP locally.
```

**Topics (copy individually, maximum 20):**

```
javascript-analysis
javascript-deobfuscation
web-scraping
web-development
web-security
static-analysis
webcrack
playwright
mcp
developer-tools
open-source
python
javascript
web-inspection
bundle-analysis
```

Only keep topics that genuinely describe the project. Avoid claims about full backend recovery or completed integrations.

## Social preview

Under **Settings → General → Social preview**, upload a PNG or JPG version of [the project banner](assets/res-banner.svg), ideally 1280×640 and under 1 MB. GitHub does not accept an SVG directly for this upload. A social preview makes shared repository links more recognizable.

## Other legitimate discovery channels

- Pin the repository on the maintainer's GitHub profile.
- Share a real demonstration and the repository link with relevant developer communities; follow their self-promotion rules.
- Keep the beta release notes, README quick start and screenshots accurate.
- Invite issues and contributions, and respond to feedback.
- Avoid fake stars, spam, keyword stuffing or claims of capabilities that are not implemented.

**Search indexing and GitHub rankings are outside the project's control.** Updating the README alone does not guarantee a higher search ranking.
